# PRD — 살래말래 × Coupicks 운영 자동화

작성일: 2026-10-04 · 버전 1.0 · 상태: 구현 전 맞춤 설계

## 1. 목적과 범위

사용자 본인의 Threads `@salraemallae.pick`과 Coupicks를 운영하는 개인용 도구를 만든다. 상품 검색, 제휴 링크 생성, 근거 확인, 글 작성, 사이트 반영, 예약 발행, 성과 기록을 하나의 운영 흐름으로 연결한다. 기존 PRD의 다중 고객 SaaS, 요금제, 결제, 고객 모집은 이번 범위에서 제외한다.

사용자는 매번 상품을 찾거나 글을 붙여넣지 않는다. 운영자는 AI/에이전트와 예약 서버이며, 사용자는 방향 변경과 예외 상황을 결정한다. 이번 대화에서 상품 검색·링크 생성·작성·발행을 맡기는 권한을 받았으므로 운영 기준 안의 일반 게시물은 매번 사용자 승인 요청 없이 처리한다. 시스템의 사실 검증은 여전히 필수이며, 새로운 외부 앱 권한 부여나 약관 동의 등 별도 확인이 필요한 행위는 해당 단계에서 확인한다.

수익은 쿠팡파트너스 제휴 전환이다. 조회수·매출을 보장하지 않으며, 성과 추적이 불가능한 구매를 특정 게시물의 매출로 추정해 표시하지 않는다.

## 3. 콘텐츠와 발행 기준

- 시간대: Asia/Seoul. 월~금 17:00, 하루 최대 1개. 최초 달력은 2026-10-05~11-01, 총 20개.
- 월·화·목: 링크 없는 관찰·질문·구매 기준. 수·금: 제휴 비교 글. 첫 달 제휴 8개, 일반 글 12개.
- 주제: 소분·보관 → 청소·정리 → 반려동물 → 책상·IT 주변용품. 뷰티 등은 다음 달 별도 검토.
- 말투: 짧고 구체적인 한국어 반말. 이모지·ㅋㅋ·질문을 모든 글에 반복하지 않는다. 과장, 공포, 희소성, 매번 구매 유도하는 끝맺음을 피한다.
- 페르소나: 생활용품 선택 기준을 정리하는 편집 계정. 직업·가족·반려동물·구매/배송 경험을 지어내지 않는다.

- 상품 정보로 확인한 장점·한계·적합한 상황을 함께 설명한다. 질병 관련 효과나 인증·최저가·판매 순위는 근거 없이 쓰지 않는다.
- 제휴 글의 첫 부분: `이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.` 현재 계정의 링크 생성 화면에서 안내한 문구다. 댓글이나 프로필 고지만으로 대체하지 않는다.
- 동일 링크 글 연속 발행 금지, 같은 상품의 제휴 소개는 기본 14일 간격. 이는 자체 운영 기준이며 플랫폼 제한 수치가 아니다.
- 2주 후 주제·시간·비중 검토. 자동으로 발행 빈도를 늘리지 않는다.

## 4. 공동 데이터 구조

상품 정보는 한 곳에서 수정한다. 초기에는 기존 `products.js`를 기준으로 확장하고, 서버는 그 데이터를 읽어 자체 DB에 동기화한다. DB는 예약·발행 상태의 기준이다. 같은 상품 설명을 파일과 DB 양쪽에서 독립 편집하지 않는다. 사이트에는 공개 가능한 상품 정보만 배포하고, 원고·토큰·실적은 서버에 둔다.

| 데이터 | 필수 내용 |
|---|---|
| 상품 | 내부 slug, 상품명, 카테고리, product/item/vendorItem ID, 정확한 옵션, 일반 URL |
| 제휴 링크 | URL, 생성 시각, 채널 식별자(지원 확인 후), 도착 옵션 검증 시각, 상태 |
| 근거 | 출처 URL, 확인 날짜, 주장별 근거, 규격·구성·주의조건, 사용 가능한 이미지 출처 |
| 가격 관찰 | 금액, 수량, 통화, 관찰 시각. 현재 가격으로 영구 표시하지 않음 |
| 경험 기록 | 출처, 실제 경험 여부, 사용 허용 범위. 일반 상품 설명과 별도 |
| 사이트 | 공개 여부, 상세 URL, 데이터 버전, 배포 커밋, 배포 확인 시각 |
| 게시물 | ID, 목적, 상품 참조 ID 목록, 최종 본문, 데이터 버전, 링크 방식, 예약 시각, 상태 |
| 발행 시도 | 고유 작업 ID, 원격 컨테이너 ID, 요청 단계, 응답, 재시도 및 원격 확인 상태 |
| 성과 | 게시물 ID/기간, 출처, 조회·댓글 등 허용 지표, 링크/채널 클릭, 수수료 집계, 수집 시각 |

외부 제휴 URL은 생성한 원문 그대로 보관한다. 추적 파라미터를 임의로 덧붙이거나 단축 URL을 재작성하지 않는다. Coupicks 유입 추적용 UTM은 사이트 URL에만 적용한다.

상태:

`상품 후보 → 근거 확인 → 링크 검증 → 사용 가능 → 재확인 필요/판매 중단`

`원고 초안 → 자동 검수 → 발행 가능 → 예약 → 발행 중 → 발행 완료`

예외 상태: `보류`, `실패`, `원격 결과 확인 필요`, `취소`. 상품 정보 변경으로 본문 근거가 달라지면 발행 가능 상태를 해제하고 재검수한다.

## 5. 일상 운영 흐름

1. 주 1회 상품 후보를 수집한다. 초기 목표 30개, 첫 제휴 글에 필요한 16개 안팎부터 우선 검증한다. 수량을 채우기 위해 질 낮은 후보를 넣지 않는다.
2. 정확한 옵션별 근거를 기록한다. 상품명만으로 전자레인지·식기세척기·급여량·충전 규격을 추정하지 않는다.
3. 동일 옵션의 기존 링크를 재사용하고 신규 옵션만 생성한다. 기존 5개와 락앤락 링크를 목록에 병합하며 중복은 외부 ID·옵션으로 확인한다.
4. 검증된 상품에서 글과 사이트 상세 정보를 만든다. 비교 차이가 부족하면 비교 글 대신 단일 제품의 선택 기준 또는 일반 글로 바꾼다.
5. 사이트 경유 글은 먼저 사이트를 빌드·배포하고 실제 URL 정상 표시를 확인한다. 배포 실패 시 사이트 경유 게시물은 보류한다.
6. 매일 16:30에 당일 상품·옵션·링크·본문의 가격 관련 주장을 재확인한다. 정상일 때만 17:00 발행 큐로 넘긴다.
7. 확인 실패 시 검수된 일반 글로 슬롯을 교체한다. 대체 글도 없으면 건너뛰고 사유를 기록한다. 품절 상품을 임의의 유사 제품으로 바꾸지 않는다.
8. 서버가 17:00에 발행하고 실제 게시물 ID·URL을 저장한다. 24시간·72시간 지표와 주간 제휴 보고서를 가능한 범위에서 수집한다.

상품 상태 확인은 공식 API가 제공하는 항목 또는 정상 접근 가능한 페이지에 한정한다. 접근 차단을 우회하지 않는다. 확인 수단이 없으면 자동 운영 가능 상태로 표시하지 않는다.

## 6. 링크 경로와 Coupicks 역할

두 경로를 지원한다.

- 빠른 상품 소개: Threads → 생성된 쿠팡파트너스 링크.
- 여러 상품 비교: Threads → Coupicks 비교/상세 페이지 → 해당 제휴 링크.

모든 글을 사이트로 우회시키지 않는다. 첫 달 직접 링크와 사이트 경유를 기록하고 비교하되, 작은 표본으로 효과를 단정하지 않는다. 사이트 경유 글에도 제휴 관계를 표시한다.

사이트의 `최저가 확인`은 `가격 확인`으로, 체험 없는 상세 페이지 진입명은 `상품 정보`로 수정한다. 기존 체험담은 출처를 보존한다. 새 비교 글은 규격·차이·맞는 상황·확인 시점을 담는다. 표시 가격은 초기 기본 숨김을 유지한다.

상품 하나 추가 시 상품 데이터 수정 → 사이트 빌드 → 생성 페이지 검증 → Git 변경 확인 → 배포 → 외부 URL 확인까지 수행한다. 원본의 진행 중인 변경은 덮어쓰지 않는다. GitHub Pages는 공개 사이트 역할이며 예약 서버·비밀키 저장소 역할을 맡기지 않는다.

## 7. 연동과 최소 구현

### 쿠팡파트너스

초기 수집은 로그인된 파트너스 UI에서 검색·링크 생성 후 저장한다. 자동 수집·갱신은 계정에서 파트너스 API 이용 가능 여부와 현재 기능을 확인한 다음 도입한다. 판매자용 쿠팡 Open API를 대신 쓰지 않는다. UI 작업은 사람이 컴퓨터를 켜두지 않아도 동작하는 예약 서버의 대체 수단으로 간주하지 않는다.

API를 사용할 수 없으면 배치 링크 생성과 근거 확인은 세션 내 운영 작업으로 남기고, 서버는 검증 완료 원고 발행만 자동화한다. 이 경우 ‘상품 검색까지 완전 무인’으로 표현하지 않는다.

### Threads

본인 계정용 Meta 앱 → OAuth → 필요한 권한 확인 → 토큰 저장 → 테스트 발행 → 서버 예약 워커 순서. 기본 접근·발행은 `threads_basic`, `threads_content_publish`를 검토하고 지표 수집에는 별도 권한을 확인한다. 본인 계정의 개발/테스터 접근과 외부 고객 공개 심사를 구분한다.

기본 예약 기능은 API 구축 전 임시 운영 수단이다. 기본 예약과 서버 예약에 같은 글을 중복 등록하지 않는다. API 발행 글에 자체 스케줄러가 시간을 부여하며, 플랫폼 기본 예약과 동일한 저장소라고 가정하지 않는다.

### 실행 환경

작은 서버 앱 하나와 SQLite, 정기 실행 작업으로 시작한다. SQLite 사용 시 영속 디스크와 단일 워커를 확보한다. 서버리스의 임시 파일시스템에 SQLite를 두지 않는다. 호스팅이 그 조건을 제공하지 않으면 관리형 관계형 DB로 변경한다. 웹 관리 화면은 최소한의 목록·편집·보류·정지 기능부터 만든다. 별도 메시지 브로커·마이크로서비스는 초기 범위에서 제외한다.

AI 공급자는 서버 환경변수로 연결하고 비용·생성 건수를 기록한다. 모델 이름·가격은 구현 시 선택한다. 토큰·시크릿은 프론트엔드, 공개 Git, 상품 파일, 원고에 저장하지 않는다.

브라우저와 Codex가 종료되어도 발행하려면 상시 실행 환경이 필요하다. 현재 채팅의 ‘계속할게’라는 응답 자체는 백그라운드 실행이나 예약 설정이 아니다.

## 9. 장애 처리

- 토큰·권한 문제: 해당 계정의 발행 중단, 재연결 요청. 새로운 권한을 임의 승인하지 않는다.
- 일시 장애: 제한된 횟수의 지수 백오프. 자체 운영 기준으로 당일 17:30을 넘기면 자동 지연 게시 대신 보류한다.
- 발행 응답 유실: 원격 상태/게시물 대조 후 판단. 결과 불명이면 확인 필요 상태로 멈추며 새 게시물을 무조건 생성하지 않는다.
- 사이트 배포 실패: 사이트 경유 원고만 차단. 새 링크와 본문으로 변경하려면 재검수한다.
- 전체 정지: 미발행 작업을 차단한다. 이미 외부 API가 처리 중인 작업은 결과 확인 후 표시하며 취소 성공을 보장하지 않는다.
- 운영 알림: 로그인 만료·발행 실패·검증 수단 상실 등 조치가 필요한 경우에만 사용자에게 알린다. 일상 보고는 주간으로 묶는다.

## 10. 성과 측정

평일 발행 수, 사실 검증 실패·중복·수정 건수, 운영 시간, AI/서버 비용, 조회·댓글·제휴 클릭·수수료를 기록한다. 게시물별 조회와 계정 전체 제휴 수익을 억지로 연결하지 않는다.

파트너스 채널 구분 기능의 사용 가능 여부와 보고서 세분도를 확인한다. 게시물별 매출 귀속이 제공되지 않으면 채널·기간 집계까지만 표시한다. Coupicks 방문 분석은 별도 도구가 연결되기 전까지 측정 완료로 표시하지 않는다.

첫 달 목표는 설정된 슬롯의 안정적 실행과 상품/원고 검증 과정 확보다. 수익 목표는 첫 달 관측 데이터가 나온 뒤 정한다. 2주 차에 주제·시간을 검토하고 4주 차에 계속 운영할 카테고리를 결정한다.

## 11. 단계별 실행

1. 데이터 정리: 기존 5개와 신규 링크 병합, 첫 주 상품 상세 검증, 원고 5개 완성. 산출물은 제품 목록과 발행 가능 원고.
2. 사이트 연결: 원본 Git 상태·사용자 변경 확인 후 문구 수정과 공통 데이터 내보내기 반영, 배포 URL 검증.
3. 발행 PoC: Meta 앱과 실제 계정 연결, 명시적인 테스트 원고로 1회 발행 및 결과 확인. 테스트 문구를 광고 원고처럼 임의 게시하지 않는다.
4. 예약 운영: 영속 서버·예약 큐·전체 정지·중복/토큰 장애 검사. 정상 조건에서 예약 후 2분 이내 발행을 내부 목표로 측정한다.
5. 상품 자동화: 파트너스 API 가능 범위를 확인해 단계적으로 연결. 불가능한 확인 작업은 보류 조건을 유지한다.
6. 주간 운영: 한 달 초안은 유지하되 제휴 상품은 주 단위 확정, 당일 재확인, 매주 결과 집계.

달력은 준비 상황에 따라 밀릴 수 있다. 연결 전 지나간 슬롯은 일괄 소급 발행하지 않으며 다음 영업일부터 재배치한다. 개발 기간과 외부 심사 완료일은 아직 확정하지 않는다.

## 12. 검증 체크

- 공동 상품 정보 수정이 사이트·원고에 함께 반영되고, 오래된 원고 버전은 재검수된다.
- 잘못된 옵션, 품절/접근 실패, 고지 누락, 근거 없는 효과·가격 주장으로 발행이 통과하지 않는다.
- 서버 재시작·중복 작업 실행·외부 응답 유실 시 중복 발행을 방지하거나 확인 필요 상태로 중단한다.
- 토큰 만료·취소·전체 정지가 미발행 작업을 막는다.
- 사이트 경유 URL의 배포 완료와 정상 페이지를 확인한다.
- 실제 계정에서 예약 발행과 게시물 URL을 확인하며 토큰이 로그·Git에 남지 않는다.
- 기존 체험 후기가 Threads의 허구 경험으로 자동 전환되지 않는다.

## 13. 확인이 필요한 외부 조건

Meta 앱의 최신 권한·본문 제한·호출 한도·토큰 규칙·본인 계정 접근 조건, 파트너스 API 이용 가능 여부와 검색/가격/재고 제공 범위, 활동 채널 등록 조건, 사이트 배포 권한, 상시 서버와 예산, AI 인증 정보와 비용. 이 조건은 연결 단계에서 확인하며 현재 가능하다고 단정하지 않는다.
